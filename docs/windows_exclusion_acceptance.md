## 唯一解释链路

排除名单原文
→ analyze_exclusion_list
→ 标准化文本、诊断、行号映射、编译规则
→ PreparedExclusions
→ iter_project_entries
→ 扫描或常规合并。

## 语法

- 只按 LF、CRLF 分行。
- 先删除所有半角双引号。
- 删除引号后第一个字符为 |：停用，正文不再标准化或校验。
- 否则第一个字符为 :：文件无扩展名条件。
- 类别和根限定只判断一次。
- 启用规则正文以单个反斜杠或正斜杠开头：限定源目录根。
- 合法启用规则的分隔符和根限定符统一保存为反斜杠。
- 普通名称完整匹配，不隐式子串匹配。
- 非根限定允许从任意层级开始。
- * 不跨目录；? 匹配一个字符；独立路径段 ** 支持零层、多层。
- 普通字符如分号、逗号、方括号、反引号不赋予旧语义或高级语义。
- 文件无扩展名采用 PureWindowsPath.suffix，并用 Path.suffix 样本回归。
- 不依赖宿主操作系统的路径解析来解释匹配模式。

## 保存与反馈

编辑、粘贴、撤销、重做、查找替换、失焦不接受名单配置。
编辑只撤销过期诊断，显示“已修改，尚未校验”。
明确保存时同时读取、处理两个名单，再回写标准化文本。

- 灰：停用，不检查正文，不触发风险确认。
- 黄：有效但有风险；弹窗列出名单、当前行号、原因和转义展示。
- 红：无效；阻止两份名单保存，不删除红项，不覆盖上次有效配置。
- 红黄并存只显示一份汇总。
- 保存失败保持窗口，恢复共享配置的原名单字段。
- 标准化回写不代表保存成功。
- 关闭时选择保存，使用与保存按钮相同的校验和提交链路。
- 收藏保存校验所属名单，不提交两个名单的业务配置。
- 收藏回填保留原文，后续正式保存才处理。

输入行号和标准化后的显示行号分别记录。
业务直接校验配置时使用原输入行号；回写后的 GUI 使用显示行号。
