## 唯一正式链路

修改：
PatchPanel.run_preview
→ patch_service.preview_patch
→ PatchExecutor.preview
→ V3 单项及全局校验
→ 固定 TaskPlan
→ 用户确认
→ patch_service.apply_patch 消费同一个预演结果
→ PatchExecutor.apply
→ 逐步保护与清单发布
→ 固定业务动作。

恢复：
PatchPanel.run_preview
→ patch_service.preview_backup_restore
→ BackupRestoreExecutor 构造
→ 全量清单、材料、安全预检及固定计划
→ 风险展示与当次确认
→ patch_service.apply_backup_restore 消费同一个预演结果
→ 全量执行前复核
→ 还原前逐步保护
→ 集中原状态恢复。

预演结果持有 execution，属于本次进程内的一次任务。
不持久化执行器，不从配置恢复执行资格。
执行器成功或失败后永久消费，必须重新预演才能再执行。
不再保留 apply_one_op 重规划入口。

预演中的 valid_patch 只是展示和部分执行选择信息，
执行权威是 execution 持有的固定计划。
界面操作摘要消费固定计划，不重新读取存在性决定范围。

## 规划和原状态

TaskPlan 固定实际动作、执行或跳过决定、
改变路径、只读源、安全状态前提、必要父目录和保护映射。

规划不复制全部材料，也不提前发布全部条目。

已有对象在首次实际涉及前观察和备份。
同一保护对象只保存一次最初原状态。

已有父目录不因为共享文件而扩大保护。
共同缺失父目录以第一层不存在目录归并。
后续动作只复用前序动作实际必然创建的必要父目录，
不按整个祖先保护范围授权任意新对象。

确认后的存在性、类型、必要父目录前提变化会停止，
不会重新规划成新创建、覆盖或删除。

恢复源清单的原始字节在确认后必须保持一致，
发生变化要求重新预演及确认。
确认后全量复核材料，再开始任何项目恢复。
耗时保护后再次复核本动作目标及源材料。

这些检查不是文件系统锁。
无法检测所有同类型内容变化，
无法消除检查与系统调用之间的竞态。
规划、备份和执行期间必须避免外部并发修改。

## 清单和布局

任务目录：
- files/：原名称、原项目相对路径的原始材料。
- recovery.json：唯一恢复依据。
- 执行日志.txt、还原执行日志.txt、修改包原文.txt：可选辅助材料。

每个任务使用时间码及 UUID 的独立目录。
临时备份使用 .名称.UUID.preparing。
无有效清单引用的材料不自动恢复。

format 唯一值：ZIPATCH_RECOVERY。
version：整数 1，与契约版本 2.1 不同。

完整顶层字段：
format、version、task_id、task_kind、project、backup_root、entries。

task_kind 为 patch 或 restore，两者使用同一恢复入口。
project 为 {"root": 规范化绝对项目路径}。
backup_root 固定为 files。

不存在条目：
path、existed=false、original_type=absent。

存在条目：
path、existed=true、original_type=file 或 directory、
backup_path、integrity。

backup_path 必须与 path 一致。
拒绝未知字段结构、版本、矛盾状态、重复或父子重叠。

本版项目身份采用实际平台规范化绝对路径。
不支持跨项目迁移；项目不一致直接拒绝。
有效空清单无需恢复，不推测散落材料。

## 完整性

文件：复用 file_content_sha256，按原始字节 SHA-256。
备份和恢复不转换编码、BOM 或换行。

目录 algorithm：sha256-tree-json-v1。
包括根目录、子目录、空目录和文件。

目录记录：
[POSIX 相对路径, 类型, 文件 SHA-256 或空字符串]。

按 UTF-8 相对路径字节排序。
JSON ensure_ascii=False，分隔符为逗号及冒号，不加入空格。
每条 UTF-8 记录前加入 8 字节大端长度，
对全部长度和记录字节计算 SHA-256。

结构枚举结果作为 ObjectSnapshot 传递给校验和持久化。
来源复制前后复核是时间边界变化后的新观察。
普通文件指纹不另建第二套实现。

指纹是损坏和不一致检查，不是真实性签名。

## 发布关口

当前动作涉及的新对象全部完成：
观察原状态
→ 复制或准备 absent 记录
→ 准备材料校验
→ 来源复制一致性复核
→ 材料持久化
→ 材料正式名称发布
→ 候选清单写入
→ flush、文件 fsync、关闭
→ 原子替换 recovery.json
→ 实际平台目录持久化
→ 固定前提复核
→ 业务改变。

隐式父目录创建位于该关口之后。
多对象动作全部准备完成后才发布新条目。

清单替换前失败：
当前动作不执行；
首次发布可能没有正式清单；
此前清单不被临时准备覆盖。

替换调用报告错误：
保守说明替换结果无法确认。

替换成功后目录持久化失败：
说明正式清单已替换；
当前业务仍不执行；
不回退旧清单，不删除可能已引用材料。

已发布条目不依赖动作完成记录。
发布后未执行业务的对象允许冗余恢复。

## 原状态恢复和还原前保护

文件恢复原始字节。
目录整体恢复原树和空目录，删除多余内容。
absent 对象恢复为不存在，目录包含当前全部内容。

只创建恢复必需的缺失父目录。
不推测其原有兄弟内容，
不删除阻塞父路径的文件、链接或特殊对象。

还原前保护共享同一机制。
必要缺失父目录可以合并为 absent 保护对象。
再次恢复该备份会删除此目录整个当前内容；
预演报告和确认弹窗展示此范围。

不存在可靠执行后状态时不声称没有后续修改。
恢复可能覆盖后续修改，也可能冗余恢复未执行对象。

## 安全和平台边界

原路径链检查先于链接解析。
拒绝符号链接、Windows 重解析点及特殊实体。
目录树检查不静默跟随链接。

Windows 拒绝非法名称、尾部句点或空格、
保留设备名称及备用数据流路径。
这不是全部文件系统别名的全面认证。

保护范围与任务目录不得重叠。
只读复制源不能递归包含本次任务目录。
恢复不能破坏源清单或源备份。
新还原前任务不能与源备份重叠。

关闭备份不检查未使用的备份路径，
但业务路径安全检查仍执行。

Windows 材料文件持久化使用可写句柄；
仅临时调整本次准备材料的基础权限。
POSIX 请求文件和目录 fsync。
Windows 标准库无等价通用目录 fsync 接口。

保留 copy2/copytree 的基础复制行为。
不承诺完整 ACL、所有者、备用数据流、
硬链接关系和其他高级元数据。

不提供整批原子事务、自动整批回滚、
项目全量快照、外部并发协调，
或所有断电、设备缓存和网络共享故障的绝对保证。

## 删除和调用点

patch_backup.py 删除旧 manifest 读写、
逐 OP 状态、漂移比较、旧备份复制及空父目录撤销能力。

PatchExecutor 删除 before/after manifest、
旧成功记录恢复依赖及单动作重新规划入口。

BackupRestoreExecutor 整体替换旧反序 OP 求逆链。
模型删除 manifest、has_mismatch。
patch_service 和 PatchPanel 同步消费新预演任务。

V3 parser、操作类型、原始协议文档不修改。
合并、扫描、拆分还原、配置持久化不重构。
