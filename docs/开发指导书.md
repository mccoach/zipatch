# Zipatch Windows 链接支持改造开发指导书

## 1. 定位与核心要求

本指导书规定 Zipatch 本次 Windows 链接支持改造的完整目标、项目边界、实施节奏和完成条件，不是通用规范的替代品，也不是运行日志汇编。

项目根目录：`E:\AppProject\zipatch`。日志中的 `E:\AppProject\Zipatch` 为同一 Windows 项目目录。

必须遵守以下三份通用规范的实际提供正文：

- `docs/AI编程最高原则与最终态执行协议.md`
- `docs/AI自驱动人机协同开发SOP.md`
- `docs/Zipatch_V3_修改包协议规范.md`

未经针对这些规范的明确授权，不得修改其正文，也不得修改运行时内置修改包协议正文。

> 核心诉求：在完整实现本指导书功能目标、满足最高原则和安全约束的前提下，用实际可承受的最少轮次，尽快完成整个改造。

“尽快完成”是实施规划和交付方式的核心要求，不是附带建议。不能只追求每轮改动很小、测试数字增加或局部能力可用，而长期不完成正式业务接入。

速度不得通过删减目标、降低校验、虚报完成、制造旁路或牺牲数据安全取得。应通过正确设计、主体批次合并、复用成熟核心、减少重复工作和集中交付来提高速度。

## 2. 整体改造目标

为 Zipatch 增加并完整接入：

1. Windows 文件软链接（file symlink）。
2. Windows 目录软链接（directory symlink）。
3. Windows 目录联接（junction）。

最终覆盖：

- 路径观察、实际正文访问和指定入口操作。
- 原状态保护、备份、主动恢复与适用的自动回滚。
- 单链接入口及含链接混合树的复制、移动、改名、删除。
- 修改包本地预演、实际范围展示和授权。
- 已展示完整固定范围的全部确认、逐操作局部跳过与依赖裁剪。
- 名义路径、实际目标、结构范围、来源和访问依赖的联合冲突检查。
- 路径扫描、目录合并、列表合并与组合合并。
- 链接结构容器输出、严格解析及尊重目标既有链接的实体拆分。
- 必要的直接界面消费者、结果说明和 Windows 回归验证。

只完成共同文件系统核心、孤立函数或底层测试，不等于完成上述业务目标。

## 3. 尽快完成的强制实施要求

### 3.1 优先压缩总工期、总轮次与返工

每轮应从剩余整体目标倒推当前最有价值的主体交付，而不是从最容易修改的文件出发。

必须：

1. 优先一次性交付当前能力范围内能够成熟完成的直接相关工作。
2. 将同一业务闭环的生产核心、直接消费者、授权、恢复、必要测试和说明尽量合并。
3. 复用已正确实现并验证的能力，不重复开发或重新交付旧包。
4. 在交付前集中检查导入、类型、接口、状态生命周期和调用关系，减少可避免的修正轮。
5. 测试反馈与下一批所需素材尽量一次集中提交，减少人工往返。
6. 已通过且未受影响的验证沿用，不机械重复。
7. 已满足完成条件的主体简短收口，直接推进下一明确主体。
8. 文档只维护直接受影响的必要位置，不将常规记录或全量文档同步变成独立开发门槛。
9. 每轮重新判断哪些剩余工作可以合并，不机械维持旧拆分。
10. 用真实需求覆盖和正式业务可用程度衡量进展，不用 OP 数量、测试数量或回复篇幅衡量完成度。

禁止：

- 将本可一起完成的生产联动拆成“一份测试一轮”“一个导入一轮”。
- 反复交付外围工具、小能力、纯格式整理，却不推进主体。
- 只输出审计、建议或计划，要求用户再次下令实施。
- 以无法独立运行本机测试或不能保证百分之百成功为由拒绝成熟交付。
- 为降低单轮工作量而制造临时接口、兼容层或计划下一轮删除的过渡方案。
- 为凑修改包而制造无实质价值的修改。
- 通过永久拦截本应完成的目标场景，把未完成能力说成最终完成。

### 3.2 允许必要拆分，但不能无止境细分

只有任务规模、强耦合改造、实际上下文承载或当前能力边界确实使单轮完整实现不可行时，才拆分。

拆分必须说明：

- 当前批次具体完成哪些最终态内容。
- 为什么剩余内容不能合理合并。
- 批次间的真实依赖。
- 尚缺哪些正式消费者及验收证据。
- 下一批如何直接推进剩余主体。

阶段载荷必须完整。中间不完整按通用规范明确隔离，不得为中间可运行建立第二条业务链，也不得将开发中间态用于重要真实数据。

不承诺固定轮数或虚构完成概率。需要给出轮次估计时，应基于实际剩余主体和反馈情况，并明确其不是保证；不能仅因估计不确定而不作实施安排。

## 4. 事实区分与路径边界

必须分别表达和维护：

- 名义入口：用户或修改包指定的位置。
- 实际目标：本次解析后访问的对象位置。
- 链接实际原定义：Windows 返回并保存的原始定义。
- 直接目标：由入口位置与原定义解释出的直接引用位置。
- 中间链接链：实际访问经过的链接，不压平为最终目标。
- 对象身份：不能以同名、同字节或同摘要代替。
- 内容事实：正文、结构及定义完整性，不以身份或时间代替。

修改包只接受项目根相对路径，不接受绝对路径、`..`、通配符路径或新增链接指令。

项目根内入口可以指向根外目标。协议路径合法不等于实际访问范围已经授权；本地预演必须展示实际范围并取得适用授权。

正文里的 `mklink`、命令行或其他文本仅为正文，不能作为执行指令。

保存的链接定义可以具有 Windows 返回的扩展前缀，但这不意味着修改包输入路径允许设备路径。

未知重解析类型、不可靠身份、非法定义和无法安全定位的对象，必须明确拒绝，不能按普通文件猜测处理。

## 5. 正文访问与入口操作语义

### 5.1 正文访问

经本次授权的内容编辑修改实际普通文件正文，并保留末级文件软链接及未作为工作对象的中间链接入口。

正文读取前完成必要的路径元信息探查、实际范围展示和访问授权。执行只消费已固定成果及适用的新边界复核，不重新定位 OLD、组合正文或询问权限。

访问依赖用于范围复核，不自动追加为备份、删除、重建或恢复对象。

普通硬链接正文编辑及现存正文恢复继续使用原对象写回机制，不扫描其他关联名称，不用名称替换伪装为保留硬链接关系。

### 5.2 入口复制、删除、移动与改名

只操作指定入口：

- 文件软链接复制消费原定义，不复制其目标正文。
- 目录软链接和 junction 作为结构叶子，不自动展开目标。
- 删除链接只删除入口，不删除目标。
- 混合树复制和移除保留链接叶子语义。
- 入口复制覆盖只替换指定名称，不写入被覆盖硬链接的共享正文。
- 原生移动保持适用对象身份，失败不能切换复制删除。
- 跨卷机制必须在预演固定；适用复制重建全部核验成功后，才允许移除固定来源。

复制或移动到不同父目录时，相对原定义保持原样，但其直接引用位置可能变化。必须展示该影响，不能改写为绝对定义或最终目标来掩盖变化。

跨卷移动不得擅自拆断普通硬链接关系。平台或既有硬链接约束确实不支持的场景应明确拒绝并说明；尚未实现的安全机制应登记为待完成，而不是永久取消目标。

## 6. 本地预演、授权、跳过和联合范围规划

链接行为由本地预演探查、展示、授权和处理，不通过修改包增加链接指令。

必须接通：

1. 名义入口、实际工作对象、链接原定义和经过的链接链展示。
2. 根内／根外实际访问范围和入口影响展示。
3. 已展示完整固定范围的一次全部确认。
4. 逐 OP 的明确局部跳过。
5. 跳过后的工作成果、备份对象、来源和访问依赖裁剪。
6. 最终未跳过范围的联合检查与固定执行计划。
7. 取消、执行尝试或失败后任务永久失效。

“一次全部确认”只能授权已经展示并固定的完整范围，不能提前授权尚未探查、未展示的后续根外访问。

局部跳过是用户的范围决定，不是校验错误的逃生通道。非法协议、类型错配、正文定位错误、材料错误和联合冲突不能通过跳过失败项来执行通过子集。

保留通用协议的整包与内容互斥规则，并联动检查：

- 名义入口与实际目标别名。
- 同一实际对象的不同访问入口。
- 复制来源与工作改变范围。
- 链接访问依赖与入口移除、移动或重建。
- 结构父子包含及源目标重叠。
- 共享硬链接正文的最终承诺。
- 工作范围与备份材料、恢复来源及辅助输出的隔离。

目录链接父链的结构访问必须单独固定名义与实际位置及依赖。只有授权、正式消费者、保护和回滚一起可靠接通后才放行，不能只解除路径拦截。

执行只复核固定计划，不现场询问、扩大访问范围或增加恢复对象。

## 7. 保护、严格依据、恢复与自动回滚

### 7.1 正式保护

沿用已有正式备份链和唯一保护投影：

- 保护实际工作对象，不将纯访问依赖变成恢复对象。
- 链接只保存实际原定义，材料为独立普通文件。
- 混合树中的链接保存为普通定义材料，不创建活动源链接，不读取引用目标正文。
- 清单、对象编号、材料位置、原结构、完整定义和摘要严格对应。
- 全部必要原备份及完成凭据成功后，才能开始首个工作修改。
- 原先不存在对象准确记录为不存在，不制造假原文件。

保持普通状态契约和现有严格 version 4 行为，不猜缺失定义、不回退旧材料布局、不增加旧版本兼容读取。

必须拒绝缺失、额外、损坏、活动链接、共享硬链接材料，以及重复字段、未知字段、定义错配、类型错配和范围矛盾。

### 7.2 恢复执行

复用已有正文发布、硬链接写回、链接重建及固定树移除核心。

所有移除和重建消费固定计划及对象身份。重建只使用固定不存在入口，不覆盖后来出现的外部对象。

原定义是重建权威，不得：

- 删除 Windows 返回的 `\\?\` 等前缀后伪称恢复原定义。
- 放宽定义比较。
- 将直接目标或最终目标替代保存原定义。
- 压平中间链接链。
- 将定义 JSON 当作目标正文。

恢复必须核验完整成果，包括链接定义、普通正文、结构和适用正式文件时间。不宣称完整元数据恢复，也不将独立重建名称说成恢复了原硬链接拓扑。

### 7.3 生命周期与失败政策

必须区分备份失败清理和恢复失败保留：

- 人类执行修改包、代码拆分及主动备份恢复均强制备份。
- 全量备份失败，在工作开始前清理本次唯一任务目录；清理失败明确提示人工处理。
- 修改包工作失败，按原固定范围及真实步骤事实尝试自动恢复原备份。
- 主动备份恢复工作失败，按本次还原前保护及真实步骤事实尝试自动回滚。
- 自动回滚不另备份、不自动重试、不自动续执行。
- 恢复或回滚失败保留原备份，并明确不能认定现场已恢复。
- 主动恢复失败时，原来源备份与已经完成的还原前保护备份均保留。
- 工作已完成后的辅助输出故障，不冒充工作未执行，也不擅自启动工作回滚。
- 代码拆分沿用当前既有失败停止政策，不因本次链接支持擅自改为自动回滚。
- 发布资格消费后，禁止通用取消清理残余；备份阶段任务目录清理使用其独立生命周期。
- 原生调用失败停止，不擅自切换机制或增加补救操作。

自动回滚只消费原固定恢复范围和真实工作步骤前缀。不能从失败现场补猜身份、补认未知创建成果或追加恢复对象。

无法可靠对应现场时必须停止。程序缺陷应保留原始上下文自然暴露，不能用过宽异常捕获伪装成普通业务失败或保证回滚成功。

## 8. 扫描、合并与结构容器

接通路径扫描、目录合并、列表合并和组合合并的真实正式入口，不仅新增底层遍历能力。

必须：

- 区分入口结构观察与实际内容访问。
- 未授权时不读取链接目标正文或展开目标目录。
- 目录软链接和 junction 不默认递归展开；确需访问目标时，先展示并授权实际范围。
- 处理悬空链接、中间链、循环及重复访问，不能无限遍历或重复生成冲突结构。
- 保留原排除、显式列表包含、顺序、正文解码、换行、占位和时间政策中未被本目标改变的语义。
- 将链接定义和普通正文分别表达，不用目标正文代替链接定义。
- 容器必须能够表达所需普通目录、普通文件和三类链接结构，不丢失链接叶子或必要空目录。
- 所有模式使用一致的结构表达和正式生成链。
- 授权、输出范围、来源与输出冲突检查及必要界面消费者同步接入。

结构容器具体字段及接口应依据正式设计和实际源码确定。本指导书不凭空预设尚未提供的字段、格式版本或函数签名。

## 9. 代码拆分与直接界面消费者

本节按用户最新明确裁决调整代码拆分政策；
不改变第5节明确入口操作、第7节备份原状态恢复及自动回滚。

代码拆分只创建普通文件和普通目录，不主动创建、移除或改指向链接：

- 普通正文按名义映射路径工作。
- 目标根、任一父层或末端已经存在链接时，取得完整原定义，
  固定实际位置，先由共同授权窗口筛选，再在实际位置取得旧正文、
  强制保护及发布；已有链接不作为工作或恢复对象。
- 普通目录记录及来源目录软链接、Junction结构记录统一成为目录要求。
  目标缺失时创建普通目录，已有目录链接经授权后沿用，
  不清空未列成员，不按来源保存定义创建链接。
- 来源文件链接结构只有定义而没有正文时，明确列为跳过：
  不补读保存定义指向的对象、不编造空文件、不将定义JSON作为正文。
  来源缺失不归咎于还原位置，结果不得宣称该项正文已经恢复。
- 来源定义不要求与目标已有定义相同；目标现场事实决定本次实际路线，
  授权后仍严格核对该现场定义，不能接受交互后改指向。
- 悬空文件链接不能定位到既有正文对象时拒绝；
  不删除链接、猜测引用目标或切换实体替换来掩盖。
- 普通文件保留覆盖／跳过、换行及硬链接原对象写回政策；
  保护与发布继续使用既有唯一正式核心。
- 未选项不取得旧正文、不保护、不执行，也不保留其工作依赖。
- 失败停止，不改变拆分既有不自动回滚的政策。

跨业务共同授权机制只拥有展示筛选及决定投影：
业务提供各自固定计划、实际关联键及风险说明；
全普通有效范围静默保留，存在链接相关项时才展示筛选，
普通项自动保留，固定跳过不可勾回。
共同分组和决定投影使用同一纯算法，不复制业务选择链。
该筛选不替代参数校验、固定范围复核、强制备份及最终执行确认。

链接原定义由共同路径观察读取：
三类链接均经同一os.readlink读取及身份、版本核验；
失败明确停止，不为历史第14项建立跟随目标的旁路。
已排除入口及未进入的目录后代不因本条而读取定义。
已有固定来源的新边界复核可比较保存身份和定义版本，
不必重新读取定义或追踪变化后的新指向。

页面、预演、完成报告、帮助及契约测试须同步反映以上最终行为。
合并成功汇总明确显示实际成功输出的普通正文文件数，
目录结构、链接入口、主动忽略、正文失败及时间缺失分别统计。

## 10. 工程与交付要求

坚持根因拉直、第一性原理和最终态直达：

- 职责清晰、高内聚低耦合、唯一事实源和唯一正式业务链。
